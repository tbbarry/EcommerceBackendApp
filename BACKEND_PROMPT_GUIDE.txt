📋 RÉSUMÉ DES 10 ENDPOINTS À IMPLÉMENTER

1️⃣  PATCH /api/admin/products/{productId}
    └─ Modifier les infos du produit (nom, prix, description, etc.)

2️⃣  POST /api/admin/products/{productId}/variants
    └─ Ajouter une variante avec attributs et stock initial

3️⃣  PATCH /api/admin/products/{productId}/variants/{variantId}
    └─ Modifier une variante (SKU, prix, attributs)

4️⃣  PATCH /api/admin/products/{productId}/variants/{variantId}/stock
    └─ Modifier le stock total d'une variante

5️⃣  DELETE /api/admin/products/{productId}/variants/{variantId}
    └─ Supprimer une variante

6️⃣  POST /api/admin/products/{productId}/variants/bulk-delete
    └─ Supprimer plusieurs variantes (ATOMIQUE)

7️⃣  POST /api/admin/products/{productId}/images
    └─ Ajouter une image (avec URL, pas de fichier)

8️⃣  PATCH /api/admin/products/{productId}/images/{imageId}
    └─ Modifier une image (alt, ordre, principale)

9️⃣  DELETE /api/admin/products/{productId}/images/{imageId}
    └─ Supprimer une image

🔟 PATCH /api/admin/products/{productId}/status
    └─ Archiver un produit

════════════════════════════════════════════════════════════════════════════════

🔐 SÉCURITÉ OBLIGATOIRE

✅ Tous les endpoints requièrent:
   - JWT valide (Authorization: Bearer {token})
   - Rôle ADMIN (@PreAuthorize("hasRole('ADMIN')"))
   - Retourner 401 si pas d'authentification
   - Retourner 403 si pas de rôle ADMIN

📊 POINTS CLÉS DE CHAQUE ENDPOINT

ENDPOINT 1: Modifier produit
  ✅ Valider: name, price, slug, categoryId
  ✅ Modifier uniquement les champs présents
  ✅ Appeler refreshProduct() après

ENDPOINT 2: Ajouter variante
  ✅ Créer Variant + Stock dans MÊME transaction
  ✅ Valider unicité du SKU
  ✅ Vérifier existence attributeValueIds
  ✅ Stock initial: quantity, reservedQuantity=0, availableQuantity=quantity

ENDPOINT 3: Modifier variante
  ✅ Vérifier appartenance au produit
  ✅ Remplacer les associations d'attributs
  ✅ NE PAS modifier le stock

ENDPOINT 4: Modifier stock
  ✅ Valider: quantity >= reservedQuantity
  ✅ Recalculer: availableQuantity = quantity - reservedQuantity
  ✅ Protéger contre modifications concurrentes (verrous)

ENDPOINT 5: Supprimer variante
  ✅ Vérifier: pas de réservations, pas de références en commandes
  ✅ Retourner 409 avec message lisible si impossible

ENDPOINT 6: Supprimer variantes (Bulk) ⚡ ATOMICITÉ OBLIGATOIRE
  ✅ Si UNE variante pose problème → RIEN n'est supprimé
  ✅ Retourner 409 avec détails du conflit
  ✅ Appeler refreshProduct() UNE SEULE FOIS

ENDPOINT 7: Ajouter image
  ✅ Valider: URL http(s), alt non-vide, displayOrder >= 0
  ✅ Si isMain=true: passer l'ancienne image principale à false
  ✅ Retourner avec champ `main` booléen

ENDPOINT 8: Modifier image
  ✅ Modifier uniquement champs présents
  ✅ Si isMain=true: passer ancienne principale à false
  ✅ Si visualAttributeValueId=null: supprimer association
  ✅ Support requête minimale: { "isMain": true }

ENDPOINT 9: Supprimer image
  ✅ Refuser si: image principale + autres images existent
  ✅ Accepter si: image principale + c'est la seule
  ✅ Retourner 409 avec message lisible si refusé

ENDPOINT 10: Archiver produit
  ✅ Valider statut "ARCHIVED" (ou valeur confirmée)
  ✅ NE PAS supprimer les données (conserve pour commandes)
  ✅ Communiquer si valeur attendue ne correspond pas

⚠️ POINTS CRITIQUES D'ERREUR

❌ Oublier refreshProduct() après chaque opération
   → L'index catalog ne se met pas à jour
   → Chercher/facettes ne fonctionnent pas

❌ Utiliser `isMain` en response au lieu de `main`
   → Frontend attend `main: boolean`
   → Désynchronisation interface

❌ Oublier l'atomicité du bulk delete
   → Si une variante échoue, les autres sont supprimées
   → Perte de données irrécupérable

❌ Autoriser réduction stock sous quantité réservée
   → Incohérence données, commandes brisées

❌ Autoriser suppression variante avec réservations
   → Référence cassée, problèmes de fulfillment

❌ Oublier transactions @Transactional
   → Création variante sans stock
   → Données orphelines

❌ Ne pas vérifier l'authentification côté serveur
   → Failles de sécurité critiques

✅ CODES HTTP ATTENDUS

✅ 200 OK: modification avec réponse
✅ 201 Created: création avec réponse
✅ 204 No Content: opération réussie sans réponse
✅ 400 Bad Request: validation échouée
✅ 401 Unauthorized: pas d'authentification
✅ 403 Forbidden: pas d'accès admin
✅ 404 Not Found: ressource inexistante
✅ 409 Conflict: conflit métier (SKU, réservations, statut)
